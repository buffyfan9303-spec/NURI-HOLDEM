## 4. 모든 묶음 공통 검증 절차

1. 담당 팀: 편집 → tsc·관련 vitest·관련 e2e(자기 43xx 포트) → 음성 대조 → 보고.
2. 독립 검증(verifier/critical/design-reviewer, 편집자와 다른 세션): 메인 체크아웃 diff 기준.
3. 리드: 파일 단위 커밋(담당표 밖 파일이 섞이면 거부).
4. 배포 전: 격리 사본(`scratchpad/ship-wt`)에서 **게이트 + e2e 전량**, 4173 은 이때만. 실패는 단독 3회 재실행으로 흔들림/결함 판정.
5. CI 확인 중 추가 푸시 금지(CI 취소 방지) → 라이브 번들 문자열 확인 → HANDOFF 한 줄.
6. DB 는 항상 `begin … rollback` 리허설(음성·양성) + 적용 전 결함 재현(대조) → 적용 → 파일 머리 ✅ 기록 → 그다음 화면 배포.
