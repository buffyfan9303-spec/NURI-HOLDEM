# 💰 Supabase 요금제 정책 — 무료 유지 기준과 상향 시점

> **원칙: 최저 요금(Free)에서 벗어나지 않는다.** 한도에 다가가면 **먼저 최적화**, 그래도 부족하면 그때 상향.
> 최종 갱신 2026-07-20 · 프로젝트 `NURI HOLDEM MAIN`(ap-northeast-2, Postgres 17) · 현재 플랜 **Free**

---

## 1. 현재 사용량 (2026-07-20 실측)

| 항목 | 사용 | Free 한도 | 사용률 | 상태 |
|---|---|---|---|---|
| DB 용량 | 20.9 MB | 500 MB | 4.2% | 🟢 |
| 스토리지 | 1.1 MB (8개 파일) | 1 GB | 0.1% | 🟢 |
| MAU(30일 로그인) | 1 | 50,000 | 0.0% | 🟢 |
| 직접 커넥션 | 20~29 | 60 | 33~48% | 🟢 |
| Egress | 대시보드 확인 | 5 GB/월 | — | 🟢 |

**커넥션 구조(중요):** PostgREST 풀 11개 + realtime/시스템 약 8~18개로 **거의 고정**.
사용자가 늘어도 커넥션은 비례해 늘지 않는다(브라우저는 HTTP/WebSocket으로 붙고 DB 커넥션은 풀이 공유).
→ **커넥션 60은 실질적 병목이 아니다.**

---

## 2. 진짜 한계선은 Egress (월 5GB)

Supabase Egress = **API 응답 + Storage 이미지** (JS/CSS 번들은 Vercel에서 나가므로 별도, Vercel 무료 100GB)

| 항목 | 값 |
|---|---|
| 포스터 이미지 평균 | 165 KB (webp, 업로드 시 자동 리사이즈) |
| 방문 1회당 Supabase Egress | 약 **0.7 MB** (이미지 4장 + API 60KB 가정) |
| 월 5GB 소진 방문 수 | 약 **7,300회** = **일 242회** |
| 캐시 적용 후(재방문 이미지 재사용) | 실질 **2~3배 여유** = 일 500~700회 |

### Egress 절감 조치(이미 적용)
- ✅ 업로드 시 webp 변환 + 리사이즈(포스터 1200×1600 q0.88, 아바타 256², 장터 1000²)
- ✅ EXIF 회전 보정 + 적응형 품질(용량 초과 시 단계 압축)
- ✅ **Storage `cacheControl: 1년`** — 재방문 시 브라우저/CDN이 처리해 전송 0에 수렴 *(2026-07-20 적용)*
- ✅ 이미지 `loading="lazy"` + `decoding="async"` — 화면 밖 이미지 미전송
- ✅ 실시간 구독 화면별 게이팅 — 불필요한 채널/응답 감소

## 3. 감시 장치 (자동)

| 장치 | 내용 |
|---|---|
| `free_plan_usage()` | DB/스토리지/MAU/커넥션 사용률 즉시 조회(관리자 화면에 카드로 표시) |
| `check_free_plan_limits()` | **70% 이상이면 운영자에게 알림**(하루 1회, 중복 방지) |
| cron `free-plan-limit-check` | 매일 **09:10 KST** 자동 점검 |
| 관리자 화면 | 내 매장 아님 → **관리자 설정 → 운영 분석** 하단 «💰 Supabase 무료 한도» 카드 |

**직접 조회:**
```sql
select * from public.free_plan_usage();
```

## 4. 상향 판단 기준 (이 조건이 되기 전에는 Free 유지)

### 🟡 관찰 (50%+) — 아무것도 하지 않는다
정상 성장. 월 1회 카드만 확인.

### 🟠 최적화 (70%+) — 요금제 대신 최적화 먼저
| 초과 항목 | 최적화 수단 |
|---|---|
| **Egress** | ① 포스터 품질 0.88→0.80 ② 목록용 썸네일 별도 생성(카드엔 작은 이미지) ③ 지난 대회 이미지 정리 ④ 이미지 CDN 앞단 캐시 강화 |
| **DB 용량** | `client_errors`·`activity_log`·오래된 `notifications` 정리(cron 이미 일부 있음), 대용량 jsonb 컬럼 점검 |
| **스토리지** | 삭제된 포스터의 고아 이미지 정리, 오래된 인증 이미지 파기(이미 승인/거절 시 삭제 중) |
| **커넥션** | (해당 없음 — 풀 구조상 고정) |

### 🔴 상향 검토 (90%+ 또는 아래 중 하나) — 그때 Pro($25/월)
- Egress가 **2개월 연속** 4.5GB 초과(최적화로도 못 내림)
- DB 450MB 초과 + 정리할 데이터 없음
- **유료 기능이 실제 매출로 연결될 때**(부스트 판매 본격화 등) — 비용이 매출로 상쇄되는 시점
- 무료 플랜의 **일시정지 정책**(7일 무활동 시 pause)이 문제가 되는 경우 → 단, 실서비스 트래픽이 있으면 해당 없음

### Pro 전환 시 얻는 것
Egress 250GB · DB 8GB · 스토리지 100GB · 자동 백업 7일 · 무활동 pause 없음 · 커넥션 상향

---

## 5. 월 1회 점검 루틴 (사장님)

1. 관리자 설정 → 운영 분석 → «💰 Supabase 무료 한도» 카드 확인
2. Supabase 대시보드 → Settings → Usage 에서 **Egress·MAU 정확값** 확인(DB로는 조회 불가)
3. 70% 넘은 항목이 있으면 위 §4 최적화 수단 먼저 적용
4. 알림이 오면(70%+ 자동 발송) 그때 확인해도 충분

> ⚠️ 무료 플랜은 **7일간 활동이 없으면 프로젝트가 일시정지**된다. 실서비스 트래픽이 있으면 무관하지만,
> 오픈 전 장기간 방치 시 주의(대시보드에서 즉시 복구 가능).
