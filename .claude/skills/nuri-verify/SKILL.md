# nuri-verify — "통과했다"를 믿기 전에 실패시켜 봐라

**어떤 검사든, 일부러 깨뜨렸을 때 실제로 빨간불이 되는 것을 보기 전까지는 아무것도 증명하지 않았다.**
초록불은 "테스트가 통과했다"이지 "그 테스트가 이 버그를 잡는다"가 아니다.

2026-09-13 세션에서 **통과하면서 아무것도 안 보던 검사**가 여럿 나왔고,
**음성 대조(깨뜨려 보기) 자체가 아홉 번 틀렸다** — 열 번째는 틀리기 **직전에 스스로 잡았다**
(기록: `.claude/handoff/current.md:1516`·`:1547`). 아래는 전부 그때 실제로 밟은 것이다.

## 경계 — 여기서 안 하는 것

| 그건 저기서 한다 | |
|---|---|
| `nuri-ship` | 게이트 실행 순서·기준선 수치·보고 형식 |
| `nuri-e2e` | E2E 실행 절차(빌드 산출물·포트·범위 좁히기) |
| `nuri-migration` | 라이브 DB 적용 절차·ACL·`search_path` |
| `security-audit` | 비밀·의존성·어드바이저 점검 |
| `nuri-time` | KST/UTC 축이 어긋나 생기는 거짓 통과의 **원인 판정** |
| `nuri-single-source` | 복제 금지 계약을 **무엇으로 세울지**(정의 단일성·배선·토큰 참조 수) |
| `nuri-affect` | 변이 0행 계약의 통로 선택과 `ALLOW`/`IDEMPOTENT_OFF` 등재 규칙 |
| `nuri-edit` | 줄끝·BOM 실측과 안전한 파일 편집 절차(아래 §1 의 변형·원복이 그 절차를 따른다) |

여기는 **검사 자체를 검사하는 방법**만 다룬다 — 저 계약들을 세운 뒤 "그게 정말 무언가를 보고 있는가"를 확인하는 절차.

## 1. 음성 대조 절차 (복사해 쓴다)

```bash
#!/usr/bin/env bash
# nc.sh <파일> <앵커> <대체문자열> -- <검사명령...>
#   예: bash nc.sh src/lib/regStatus.ts "if (target <= 0) return null;" "if (target < 0) return null;" -- \
#         npx vitest run src/lib/regStatus.contract.test.ts
#   종료코드: 0=✅ 대조 성립 · 1=🔴 검사가 안 본다 · 9=대조 무효(앵커 != 1회)
# ⚠ 앵커는 **반드시 소스에서 직접 세서** 골라라. 이 예의 초판은 `num >= 0` 이었는데 그 문자열은
#   regStatus.ts 에 **0회**다(실제 코드는 `num >= target` — `:53`·`:54` 2회 + `:45` 주석 1회) — 계약 테스트의 **제목**
#   (`regStatus.contract.test.ts:162` 가 옛 복제본의 버그를 설명하며 쓴 문구)에서 옮겨 적은 것이었다.
#   그대로 돌리면 `ABORT: 앵커 0회 매칭` · exit 9 로 **아무것도 대조하지 못한다**(2026-09-13 검증에서 잡혔다).
set -euo pipefail
F="$1"; ANCHOR="$2"; REPL="$3"; shift 3
if [ "${1:-}" = "--" ]; then shift; fi   # ⚠ `[ … ] && shift` 로 쓰면 set -e 가 여기서 스크립트를 죽인다

BAK="$(mktemp)"; cp -- "$F" "$BAK"
REF="$(mktemp)"; cp -- "$F" "$REF"
# ① 무슨 일이 있어도 되돌린다 + 되돌린 것을 바이트로 증명한다
trap 'cp -- "$BAK" "$F";
      if cmp -s "$F" "$REF"; then echo "[원복 ✓ 바이트 동일]"; else echo "🔴 원복 실패 — 직접 확인하라"; fi;
      rm -f "$BAK" "$REF"' EXIT

# ② 앵커 유일성 — 1회가 아니면 파일을 건드리기 전에 멈춘다
python - "$F" "$ANCHOR" "$REPL" <<'PY'
import sys
p, a, r = sys.argv[1], sys.argv[2].encode(), sys.argv[3].encode()
b = open(p, 'rb').read()
n = b.count(a)
if n != 1:
    # ⚠ sys.exit('한글') 은 Windows 콘솔 코드페이지에서 깨진다 — stderr 에 UTF-8 로 직접 쓴다
    sys.stderr.buffer.write(f'ABORT: 앵커 {n}회 매칭(1이어야 한다) — 파일을 건드리지 않았다\n'.encode())
    sys.exit(9)
open(p, 'wb').write(b.replace(a, r))   # 바이트 치환: 줄끝·인코딩을 건드리지 않는다
PY
# ③ 변형이 정말 그 줄에 닿았나 (2>/dev/null: 저장소 밖이면 git 이 usage 를 통째로 토한다)
echo "[변형 적용]"; git --no-pager diff --stat -- "$F" 2>/dev/null || true

# ④ 검사 실행 — 통과하면 그게 문제다
#   ⚠ 판정을 **종료코드로도** 내보낸다. 화면의 🔴 만 두고 exit 0 을 돌려주면 여러 앵커를 루프로 도는
#     호출부·CI 가 "전부 성공" 으로 읽는다 — 이 문서가 경고하는 바로 그 거짓 초록이다.
if "$@"; then
  echo "🔴 통과했다 — 이 검사는 그 줄을 보고 있지 않다"; VERDICT=1
else
  echo "✅ 실패했다 — 검사가 실제로 그 줄을 지킨다"; VERDICT=0
fi
exit "$VERDICT"
```

**실측(2026-09-13, 위 블록을 이 파일에서 그대로 뽑아 임시 파일 4케이스로 돌렸다 — 작성 시 1회, 독립 검증에서 1회 재현):**

| 케이스 | 출력 | 종료코드 | 원복 |
|---|---|---|---|
| 앵커 2곳 | `ABORT: 앵커 2회 매칭(1이어야 한다) — 파일을 건드리지 않았다` | 9 | 무변조 |
| 앵커 0곳 | `ABORT: 앵커 0회 매칭(1이어야 한다) — 파일을 건드리지 않았다` | 9 | 무변조 |
| 앵커 1곳 + 검사가 그 줄을 본다 | `✅ 실패했다 — 검사가 실제로 그 줄을 지킨다` | 0 | `[원복 ✓ 바이트 동일]` |
| 앵커 1곳 + 검사가 안 본다 | `🔴 통과했다 — 이 검사는 그 줄을 보고 있지 않다` | 1 | `[원복 ✓ 바이트 동일]` |

네 케이스 뒤 `cmp` 바이트 동일 · `sha256sum` 전후 일치.
⚠ 이 스크립트는 지금까지 **세 군데가 틀려 있었다** — `[ … ] && shift` 가 `set -e` 에 걸려 죽었고,
저장소 밖에서 `git diff` 가 usage 를 200줄 토했고, **🔴 판정에도 exit 0 을 돌려줬다**(앞 두 개는 작성 중,
세 번째는 독립 검증에서 잡혔다). **대조 도구부터 한 번 돌려 보고, 종료코드까지 확인하고 써라.**

예시 앵커가 실제로 대조를 성립시키는지도 격리 실행으로 쟀다(2026-09-13):
`if (target <= 0) return null;` 은 `regStatus.ts` 에 **정확히 1회**, 이것을 `target < 0` 으로 바꾸면
`msToRegClose(regCloseLevel=0, …)` 반환이 **`null` → `0`** 으로 뒤집힌다 —
`regStatus.contract.test.ts:164` 의 `.toBeNull()` 이 그 값을 단언한다(다른 두 단언은 그대로 통과하므로 딱 1건만 실패한다).

### 규칙 5개 (전부 실제 사고에서 나왔다)

1. **백업 먼저, 원복은 `trap` 에.** 2026-09-13 스크립트가 `npx` 를 못 찾아 **원복 전에 죽어 변형이 실저장소에 남았다.**
   그 전에도 인코딩 오류로 중단돼 파일이 변조 상태로 남은 적이 있다(`git diff` 로 찾아 복원).
   ⚠ 원복에 `git checkout -- <파일>` 을 쓰지 마라 — 다른 에이전트의 동시 편집까지 지운다. 백업 사본으로 되돌려라.
2. **앵커 유일성을 먼저 단언한다**(`!= 1` 이면 중단). 실제로 두 번 사고를 막았다(`P3`·`NC-B`, 각각 앵커 2곳에서 파일 전 중단).
   안 세서 `String.replace` 가 **바로 앞줄 다른 컴포넌트의 같은 문장**을 쳐 엉뚱한 파일이 변조된 적이 두 번 있다.
   앵커는 **컴포넌트·함수 이름까지** 포함해 고유하게 잡아라.
3. **앵커에 줄끝을 넣지 마라.** `\n` 을 넣은 앵커가 CRLF 파일에서 **조용히 0회 매칭**돼 9종 중 6종이 대조 없이 "통과"했다.
   이 저장소는 **파일마다 줄끝이 다르다.** 2026-09-13 실측:
   `TournamentClock.tsx`(CRLF 1533) · `LiveGamesTab.tsx`(CRLF 577) · `api/clock.ts`(CRLF 571) /
   `ClockDisplay.tsx`(LF 690) · `lib/regStatus.ts`(LF 97) · `api/_mustAffect.ts`(LF 66).
4. **원복은 눈으로 보지 말고 `cmp` / `sha256sum` 으로 바이트 증명**한다. 줄끝·BOM 이 바뀌면 "원복했다"가 거짓이 된다.
5. **정규식이 든 스크립트는 파일로 써서 실행한다.** heredoc·`node -e` 를 거치면 백슬래시가 한 겹 깎인다.
   이번 세션 실측: `node -e` 안의 `\.test\.ts$` 가 깎여 `SyntaxError: missing ) after argument list`.
   과거엔 파이썬 heredoc 에서 문자 클래스가 깨져 **테스트 파일이 통째로 파싱 실패**했다(→ 아래 `Tests no tests`).

### ⚠ 대조 전에 줄끝을 재라 (절차는 `nuri-edit`)

앵커가 줄끝을 타면 **조용히 0회 매칭**되고, 그 0건을 "회귀 없음"으로 읽는 순간 대조 전체가 거짓이 된다.
그래서 대조 전에 줄끝을 재는 것은 편집 위생이 아니라 **대조 유효성 조건**이다 —
이 문서가 §1 규칙 3 에서 앵커에 `\n` 을 금지하는 이유가 그것뿐이다.
**재는 법·`grep -c $'\r'` 를 쓰면 안 되는 이유·도구별 CRLF/BOM 보존 여부는 전부 `nuri-edit` 에 실측으로 있다.**
여기서 되풀이하지 않는다(그 수치가 갱신되면 한 곳만 고쳐야 한다).

## 2. 음성 대조가 0건이면 — **코드가 아니라 대조를 먼저 의심한다**

세 가지를 순서대로 확인한다.

① **변형이 정말 그 줄에 닿았나** — 앵커 매칭 횟수, `git diff` 로 눈으로 확인.
② **검사가 실제로 실행됐나** — 파일 수·테스트 수를 본다(아래 §3-3).
③ **그 줄의 메시지로 터졌나** — 다른 가드가 먼저 터진 것이 아니라.

이 저장소가 실제로 밟은 실패 목록(전부 "0 실패"로 보였다):

| 무엇이 틀렸나 | 증상 |
|---|---|
| 앵커가 이웃을 쳤다 (×2) | 다른 컴포넌트의 같은 문장이 바뀌어 **엉뚱한 곳의 게이트**가 떨어졌다 |
| 검사 문자열이 **본문 주석에도** 있었다 | SQL 자가검사 8종 중 2종이 주석 덕에 통과 |
| 변형이 다른 것을 때렸다 | 인덱스 정의를 바꾸고 `insert` 문은 못 건드렸다 |
| 변형이 **빌드를 깨뜨렸다** | 미사용 import 가 생겨 테스트가 아예 안 돌았는데 출력에 "failed" 가 없어 0 실패로 읽었다 |
| CRLF/LF 앵커 0회 매칭 | 9종 중 6종이 변형 없이 통과 |
| **낡은 산출물을 검사했다** | 4173 에 이미 뜬 preview 가 옛 `dist` 를 서빙 · 잔존 `vite preview :4174` 로 검증자 **첫 패스가 오염**됐다(§7-4-2) |
| **아무도 안 부르는 함수를 검증했다** | 호출부만 되돌렸는데 단위 테스트가 함수를 직접 import 해서 통과(`pickLiveClock`) |
| 측정 순서 | 요청 로그를 클릭 **뒤에** 비워 이미 나간 6건을 지우고 거짓 FAIL 을 낼 뻔했다 |

> 위 표는 9건이다(앵커 이웃 침범이 ×2). **열 번째는 틀리기 직전에 스스로 잡았다** — 원칙 ③("그 줄 때문에
> 터졌나")의 실물이고, 표의 `아무도 안 부르는 함수` 행이 그것이다. 함수는 맞는데 화면이 안 부르는 경우.

## 3. 통과를 의심하는 체크리스트

**1) 이 검사가 0건을 찾아 공허하게 통과할 수 있는가?**
전수 스캐너에는 **하한을 둔다**. 실물 `src/api/mutationAffected.contract.test.ts:240-245` —
`expect(sites.length).toBeGreaterThanOrEqual(80)` + 확인된 것 `>= 70`.
스캐너가 **읽을 수 없는 입력을 조용히 버리지 마라** — `(unparsable)` 로 올려 계약을 깨라(`:217-222`).
실제로 `.from(\`community_posts\`)` 의 백틱 하나 때문에 **확인 없는 DELETE 가 계약에서 사라지고 13개 전부 통과**했다.

**2) 개수만 보는가?**
`expect(n).toBeGreaterThan(2)` 가 목킹한 **8행 중 4행이 필터로 사라져도** 통과했다.
`n >= 8` 로 올려도 그 결함은 **여전히 통과한다**(일정 1건이 카드 2개를 렌더한다).
→ **무엇이 보여야 하는지를 이름으로 단언해라.** 두 픽스처 날짜 라벨이 **둘 다 화면에 있는가**로 바꾸자,
되돌렸을 때 2건이 `9/14 일정 행이 한 장도 안 보인다`로 실패했다.
(같은 부류: 항등식 테스트가 **양수 보정만 봐서 클램프 구간을 아예 안 밟고** 통과하고 있었다. 4608조합 전수로 바꾸자 드러났다.)

**3) 검사 대상이 실제로 실행됐는가?** — 수치를 매번 적는다.

```
npx vitest run <파일...>      # 실측 2026-09-13 (vitest 4.1.11):
                              #   세 계약 테스트 → Test Files 3 passed / Tests 35 passed / 1.73s
npx vitest run src/lib/__nope__.test.ts
                              #   → "No test files found, exiting with code 1" · EXIT=1
```
⚠ 파일이 **파싱 실패**하면 `Tests no tests` 가 뜬다 — "실패 0"이 아니라 **"테스트가 없다"**이다.
(2026-09-13 실제 발생 — 파이썬 heredoc 이 문자 클래스의 백슬래시를 깎아 계약 파일이 통째로 깨졌다.
이건 내가 재현한 것이 아니라 **그날의 기록**이다. 위 `No test files found` 만 내가 직접 쟀다.)
"0 failed" 만 보지 말고 **파일 수·테스트 수**를 기준선(`nuri-ship`)과 대조해라.

**4) 교차 신호가 일치하는가?**
`psql` 에 마이그레이션을 **stdin 으로 안 넘겨 아무것도 실행되지 않았는데** 로그가 비어 "변경 0건"처럼 보였다.
단서는 **ACL 이 `anon=true` 로 남은 것**이었다(마이그레이션은 항상 회수한다).
같은 하네스의 `exit=0` 도 마이그레이션이 아니라 `ON_ERROR_STOP` 미지정 탓이었다.
→ **단일 신호로 판정하지 마라.** 로그·종료코드·부수효과(ACL·행 수·해시) 중 최소 둘이 같은 말을 해야 한다.

**5) 검사가 자기 판정기를 쓰는가?**
마이그레이션 자가검사가 치환과 **같은 판정기**를 쓰면 판정기 자체의 결함은 파일이 스스로 못 본다.
ACL 자가검사는 더 고약하다 — 이미 REVOKE 된 함수를 `CREATE OR REPLACE` 로 덮으면 **파일에서 REVOKE 를 빼도 ACL 이 남아 통과**한다.
→ **ACL 음성 대조는 `DROP` 후 적용해야 한다.** (절차 자체는 `nuri-migration`.)

**6) 단언이 함수를 직접 import 하는가?**
그러면 **아무도 안 부르는 함수**도 통과한다. **배선 앵커**(import 줄 + 정확한 호출부)를 따로 둬라 —
`src/lib/clockLevel.contract.test.ts:61-92`, `src/lib/regStatus.contract.test.ts:54-68` 가 실물이다.

## 5. 계약 테스트가 **통과하면서 거짓말하지 않게** 하는 규율

> 어떤 계약을 세울지는 `nuri-single-source`(복제 금지)·`nuri-affect`(변이 0행)가 정한다.
> 여기는 **세운 계약이 실제로 무언가를 보고 있는지**만 다룬다. 이 저장소의 계약은 "13개 전부 통과"인 채로 **세 번** 구멍이 나 있었다.

**머리말에 다섯 가지를 적는다** — 이 저장소의 관행이다.
실물: `src/lib/regStatus.contract.test.ts:1-14` · `src/api/mutationAffected.contract.test.ts:1-24` · `src/lib/clockLevel.contract.test.ts:1-21`.

1. **왜 계약인가** — 실제로 났던 사고와 날짜(예: "F2 수정이 세 벌 중 한 벌에만 들어갔다").
2. **이 파일이 보는 것** — 번호를 매겨.
3. **이 파일이 못 보는 것** — ⚠ **반드시.** "이름을 바꾼 복제본은 못 잡는다", "문장의 존재만 보고 도달은 못 본다"처럼 구체적으로.
   시도했다 기각한 대안과 **기각한 실측 근거**까지 적어라(`regStatus.contract.test.ts:70-78` 이 표본이다).
4. **음성 대조 방법** — "어느 파일에 무엇을 다시 넣으면 어느 테스트가 실패하는가" 한 줄.
5. **실행 명령** — `npx vitest run <경로>`.

**쓰면 안 되는 것**

- **정규식을 템플릿으로 조립하지 마라.** 테이블·컬럼 이름을 패턴에 끼우다 이스케이프가 한 겹 깎여
  `Invalid regular expression` 이 났다. 더 나빴다면 **조용히 무엇이든 매치하는 패턴**이 되어 계약이 공허해진다.
  → 문자열 포함 검사로 바꿔라(`mutationAffected.contract.test.ts:126-129` 의 `hasCall()`).
- **정규식으로 코드와 문자열을 가를 수 없다.** 주석 제거를 정규식으로 했더니 템플릿 리터럴의 `//` 를 주석으로 먹어
  그 줄의 `.delete()` 가 통째로 사라졌다. → 문자 단위 스캐너로(`:98-124` 의 `stripComments`, 길이 보존).
- **예외 목록의 사유를 산문으로 두지 마라.** `본인 행` 이라는 네 글자가 있기만 하면 통과했다 —
  **기계가 읽는 선언**(`본인 행(user_id)`)으로 쓰고 그 주장을 코드로 검증해라(`:364-388`). 등재 규칙 자체는 `nuri-affect`.
- **증거 구간을 넓게 잡지 마라.** ±400자 창 안에 **무관한 다른 증거**가 들어와 거짓 통과했다(실제 필요 거리는 103자).
  창을 좁히고, 사이에 다른 후보가 끼면 실패시켜라(`:348-360`).
- **검사가 스스로를 만족시키는 구조인지 보라.** 켜기/끄기가 같은 함수 안에 있으면 끄는 문장이 스스로 증거가 되어
  검사가 **구조적으로 무효**가 된다 — 증거를 찾기 전에 **검사 대상 문장을 본문에서 빼라**(`:342-343`).

**판정기 자체의 단위 테스트를 같이 써라.** 소스를 변조하지 않고 계약을 고정하는 방법이고 더 오래 간다 —
`mutationAffected.contract.test.ts:401-418`(인정 4형·거부 2형) · `:421-425`(꼬리 주석 제거, URL 의 `//` 보존).

**계약이 틀린 동작을 고정하고 있으면 뒤집는 것이 맞다 — 단, 뒤집는 이유를 테스트 주석에 남긴다.**
실물 2건: `src/components/features/clock/remoteContract.test.ts`(리모컨 `liveStats` 재계산 금지가
**리모컨으로 누른 탈락을 TV 보드에 못 보내고 있었다**) · `src/api/community.deletePost.test.ts`(0행이면 던진다는 단언).

## 6. 검증자(verifier)를 언제 부르고, 왜 보고를 재현하는가

**부른다**: ① 라이브 영향·보안·권한·금액이 걸린 변경 ② **한 번 고쳤는데 또 난 부류**
③ "내가 만든 검사가 내 코드를 본다"는 자기참조 구조 ④ 완료 선언 직전.

**보고를 그대로 믿지 않는 이유 — 양방향으로 실증됐다.**
- 검증자가 **내 주장 4개를 뒤집었다**: 내가 "복제본을 만들어도 호출을 안 바꾸면 무해하다"고 단언한 것을,
  **다섯 번째 화면에 이름 바꾼 복제본을 넣고 '마감'을 렌더**해 11개 테스트 전부 통과시키며 반증했다.
- 반대로 검증자가 **폰트 "요청 0건"**(woff2 를 아예 안 받는다)이라 보고했는데 담당 프로브는 **13건·321KB** 를 쟀다 —
  잔존 preview 서버(4174, 실저장소 `dist`)의 오염이 원인일 **가능성**으로 기록돼 있다(`:337` 의 `[추정]`. 확정이 아니다).
- 검증자 스스로 기록한 자기 실수 2건: CRLF 앵커가 조용히 0회 매칭 · 요청 로그를 클릭 **뒤에** 비워 거짓 FAIL.

**규칙**
- 보고는 **행 수·동작·해시** 같은 확인 가능한 수치로 받는다. **diff 만으로는 부족하다**(적용 전/후 행 수를 둘 다 요구해라).
- **겹치지 않는 각도로 내가 1~3종을 따로 건다.** 이 세션에서 그때마다 새 결함이 나왔다.
- **실저장소 편집을 허용하지 마라.** 지시가 "격리 사본만"이었는데도 실저장소 2개 파일을 편집했다 되돌린 일이 있다.
- 검증자가 PASS 를 내도 **내가 게이트를 독립 재실행**한다(수치가 일치하는지).
- **무엇을 브리핑에 담아야 결함이 나오는지는 §7.**

## 7. 검증자 브리핑 — **무엇을 주면 결함이 나오는가**

§6 은 *언제* 부르는가다. 여기는 **손에 무엇을 쥐여 주는가**다.

2026-09-13 세션에서 독립 검증자를 **3회** 돌렸고 **매번 새 결함이 나왔다 — 4건 → 4건 → 6건**
(`.claude/handoff/current.md:2021`·`:2173`·`:2352`). 3차 6건 중 **하나는 2차 대응으로 내가 방금 만든 회귀**였다(아래 B2).
**한 회차가 PASS 라는 것은 다음 회차가 깨끗하다는 뜻이 아니다.**

### 7-1. 결함이 나온 브리핑의 공통점 (5가지)

1. **주장을 검증 가능한 문장으로 쪼개 준다.** "검토해 줘"로는 아무것도 안 나온다.
   실제로 **깨져 나온 단언들** — 브리핑에 이 형태로 올려라: *"F3-1~F3-4 **네 구멍이 닫혔다**는 주장을 깨 봐라"* ·
   *"**`where` 는 전부 필터라 손대지 않는다** — 이 안전 근거를 반증해라"* ·
   *"복제본을 만들어도 **호출을 안 바꾸면 무해하다** — 이걸 깨 봐라"*.
   뒤의 두 단언은 **둘 다 거짓으로 밝혀졌다**(`CASE WHEN` 은 가드일 수도 **필터일 수도** 있다 —
   격리 실측 **NULL 세션 0행 → 2행** / 이름 바꾼 복제본을 **다섯 번째 화면에 새로** 넣으면 11개 테스트가 전부 통과한다).
   쪼개지 않으면 검증자는 **무엇을 공격해야 하는지 모른다.**
2. **"내 하네스를 재사용하지 마라"고 못 박는다.** 같은 도구를 쓰면 **같은 사각**을 본다.
   반대 방향으로도 실증됐다 — 내가 상대 하네스를 안 쓰고 **새 컨테이너·새 DB·내가 만든 케이스 9종**으로
   다시 돌려서야 결론이 확정됐다(`:1979`).
3. **"통과를 확인하는 것보다 내가 놓친 것을 찾는 것이 더 가치 있다"** 고 **적는다.**
   이 문장이 없으면 보고가 PASS 체크리스트로 수렴한다.
   ⚠ 정직하게: **브리핑 원문은 세 회차 다 기록에 없다**(`current.md` 전문에 "브리핑" **0회** — 직접 셌다).
   남은 것은 1차의 목표 문장 *"verifier PASS 일 때만 완료"* 뿐인데(`:2023`) **그 반대 프레이밍으로도 결함 4건이 나왔다.**
   즉 이 항목은 결과에서 **역추론한 권고**이지 대조 실험이 아니다. 그래도 운에 맡기지 말고 **시켜라.**
4. **판정을 행 수·실제 동작으로 요구한다 — `diff` 만으로는 부족하다.**
   실물 판정표: `D1 필터` **0행 → 0행**(노출 없음) · `D1-flip` **2행 → 2행**(기능 소실 없음) ·
   `D2 조건식 안 CASE` **`ok`(fail-open) → `ERROR: denied`**(가드 복구). *"diff 3줄"* 은 이 중 무엇도 증명하지 않는다.
   (받는 형식·재실행 규율은 §6.)
5. **뚫어 볼 공격 아이디어를 예시로 준다.** 예시가 있으면 검증자가 **그 부류를 확장**한다.

**브리핑에 그대로 붙여 쓰는 공격 목록** (전부 이 저장소에서 실제로 통했거나 시도된 것):

- 연산자 **양옆 공백·개행**, 무공백 `!=`, 한 줄에 가드 2개
- 조건식 한가운데 **주석 삽입** `/*…*/`, **꼬리 주석**, 주석·메시지 문자열에 같은 문구 심기
- **중첩 CASE**(`if (case … end) = 1 and 가드 then`), 중첩 달러 인용 `$q$`, 서브쿼리 괄호, 오버로드 동명 함수
- JS: **백틱** `` .from(`community_posts`) `` · **템플릿 리터럴 안의 `//`** · **문자열 리터럴로 import 위장**
- **문장 끝 앵커가 없는 관용구**에 값 덧붙이기 — `u.user?.id ?? 남의id` · `await currentUser() ?? {id:남의id}`
- **구조분해 재정의** `const { currentUser } = {…}` (`const\s+` 로는 안 잡힌다)
- **앵커에서 멀리** 두 번째 위반 심기 — 1400자 밖에 두 번째 폴러를 심자 **18/18 통과**했다
- **이름을 바꾼 복제본을 새 화면에** 추가(기존 호출부를 바꿀 필요가 없다)
- 증거 창 안에 **다른 테이블의 같은 증거**를 끼워 넣기(400자 창이 무관한 upsert 를 근거로 먹었다)

### 7-2. 돌려받을 형식 — **실행 가능한 우회 입력**

가장 값졌던 보고는 분석문이 아니라 **그대로 붙여 넣으면 재현되는 코드 조각**이었다.
3차 검증자가 준 **B1~B7 이 그 형태**였고, **7종 전부 재현 → 수정 → 재확인(7/7 잡힘)** 이 됐다(`:2374`).

| # | 준 것(그대로 붙일 수 있는 입력) | 뚫린 이유 |
|---|---|---|
| B1 | `` .from(`community_posts`) `` | `['"]` 만 봤고, 못 읽으면 `continue` 로 **변이를 조용히 버렸다** |
| B2 | `` `${p}//${h}` `` 가 든 줄의 `.delete()` | **내가 2차 대응으로 넣은 회귀** — 주석 제거 정규식이 코드를 삼켰다 |
| B3·B4 | `u.user?.id ?? 남의id` / `await currentUser() ?? {id:남의id}` | 관용구에 `;` 앵커 없음 |
| B5 | `const { currentUser } = {…}` | 구조분해를 안 봄 |
| B6 | 문자열 리터럴로 import 위장 | 원문 전체 `toMatch` (줄 첫머리 앵커 없음) |
| B7 | `followVenue` 의 `23505` 제거 | 증거 창 **400자**가 너무 넓었다(실제 필요 거리 103자) |

**그래서 브리핑에 이렇게 쓴다**:
> *"결함을 찾으면 설명 대신 **내가 그대로 넣어 재현할 수 있는 입력**을 줘라 —
> 어느 파일 · 어디에 · 무엇을 넣고 · 어느 명령을 돌리면 · 무엇이 나와야 하는가(행 수·테스트 이름)."*

받은 뒤가 내 몫이다: **넣어서 재현 → 고침 → 같은 입력을 다시 넣어 이번엔 잡히는지 확인.** 셋 다 해야 끝이다.

### 7-3. 보고를 그대로 믿지 않는다 — 재현 절차를 받아 **내가 다시 잰다**

§6 이 "왜 재현하는가"를 다룬다. 여기서는 **실패가 아니라 거짓 통과가 진짜 문제였던** 한 건을 남긴다.

검증자가 *"**피연산자가 함수 호출 괄호**인 후위 `IS` 술어가 자동 치환으로 빠진다"* 고 보고했다
(`if my_role() <> coalesce(v_x,'admin') is not true then` — `supabase/migrations/20260913a_null_safe_admin_guards.sql:150-153`) — **기제는 맞았다.**
그런데 예고된 결과(읽기 확대)는 **실측에서 재현되지 않았다**: 치환 결과가 PG 문법 오류라
**트랜잭션 전체가 롤백**되어 정의가 하나도 안 바뀐다 — 조용히 틀리는 게 아니라 **시끄럽게 멈춘다.**

⚠ **이 문단을 이 문서가 먼저 뒤집어 적었다**(2026-09-13 적대적 검증에서 잡힘). 초판은 *"괄호 **없는** 후위 `IS` 술어가 빠진다"* 였는데,
`괄호 없는 후위 술어`는 그 파일이 **이미 검토로 내리고 있던** 부류(`:325` 의 N2)다 — 빠지는 것은 **정반대**다.
아래 셋째 규율("검증자 문장을 그대로 옮겨 적지 마라")을 쓰면서 **그 문장을 옮겨 적다 뒤집은 것**이라, 규율의 표본이 규율을 어긴 꼴이다.

진짜 결함은 코드가 아니라 **파일의 공시가 거짓**이었던 것이다(헤더는 *"괄호가 있든 없든 검토"* 라고 적어 뒀다).
그래서 **판정기를 고치지 않고 공시를 실측값으로 고쳤고**, 주석만 바꾼 뒤 **하네스를 다시 돌려 결과가 동일**함을 확인했다.

→ 규율 셋:
- **예고된 피해 등급까지 내가 잰다.** "보안 구멍" 과 "시끄러운 실패" 는 대응이 다르다.
- **기제가 맞다고 결론까지 맞는 것은 아니다.** 검증자 문장을 그대로 옮겨 적지 마라.
- **판정기를 못 고치면 공시를 고쳐라.** 단, 공시를 고친 뒤에도 **하네스를 다시 돌려** 결과 불변을 확인한다.

### 7-4. 검증자에게 **주지 않는 것** / 보고에 **요구할 것**

**주지 않는다**

| 금지 | 왜 (실제 사고) |
|---|---|
| 실저장소·보호 파일 편집 권한 | 지시가 "격리 사본만" 이었는데 **실저장소 2개 파일을 편집했다 되돌린** 일이 있다(`:691`). 격리 사본을 만들어 주고, 경로를 명시해라. |
| `npm run test:e2e` | webServer 의 build 가 보호 파일 `public/sitemap.xml` 을 **덮는다**. 검증자도 이걸 "확인하지 못한 것"으로 적었다(`:1758`). 돌려야 하면 `nuri-e2e` 절차(이미 뜬 preview + `E2E_BASE_URL`)로만. |
| `npm run test:mutation` | 소스 파일을 **실제로 덮어썼다가** 되돌린다(§4). 동시 편집 중에는 금지. |
| 운영 DB 접속·쓰기 | 라이브다. DB 확인이 필요하면 **격리 컨테이너**(`nuri-migration`). |
| 커밋·푸시·브랜치 이동·`git stash` | 4개 팀 동시 편집 중 `git stash` 로 **남의 미커밋 작업이 날아갈 뻔했다**(`:204`). |

**보고에 요구한다** (없으면 그 보고는 미완이다)

1. **바이트 원복 증명** — `cmp` / `sha256sum` 전후 일치, **줄끝·BOM 유지까지**.
   실물 형식: *"`calendar.ts` 바이트 동일 원복"* · *"`clock.ts` 바이트 동일(CRLF 544 유지)"* · *"블롭 해시 일치"*.
   ⚠ 저 `544` 는 **그날의 값**이다 — 지금 `src/api/clock.ts` 는 **CRLF 571**(직접 셌다 · §1 과 같은 값).
   요구하는 것은 **수치가 아니라 형식**이고, 값은 상대가 **시작·끝 두 번** 직접 재서 같아야 한다.
   (재는 법은 `nuri-edit`.)
2. **정리 완료 선언** — 격리 컨테이너 drop · 임시 파일 삭제 · **띄운 서버·백그라운드 프로세스 종료**.
   안 하면 **다음 측정을 오염시킨다**: 다른 세션이 남긴 `vite preview :4174`(PID 44232, **실저장소 `dist`** 를 서빙)가
   검증자의 **첫 패스를 오염**시켰다 — 검증자가 `curl -sI` 콘텐츠 타입 불일치로 **스스로 잡아** 보고했고
   (`.claude/agent-memory-local/verifier/project_doc5_font_verifier_2026-09-12.md:38`),
   폰트 항목(요청 0건 vs 실측 13건·321KB)까지 물들었는지는 기록에 **`[추정]`** 으로 남아 있다(`current.md:337`).
   하위 에이전트가 남긴 **CPU 무한 루프 12개**는 코어를 72분 태워 preview 가 180초 안에 못 떴다(테스트 실패가 아니었다 — `:97`·`:203`).
3. **"확인하지 못한 것" 목록** — 안 돌린 게이트 · 미조회 DB · **정적 추적만 한 항목**.
   실물: *"전체 E2E 미실행 · `build`/`lint`/`bundle:budget` 미실행 · 운영 DB 미조회 · FAIL ① 은 실브라우저 재현 안 함"*.
4. **자기 실수도 보고에 넣을 것.** 검증자가 스스로 적은 2건이 실제로 내 판단을 살렸다 —
   CRLF 앵커가 **조용히 0회 매칭**(9종 중 6종) · 요청 로그를 클릭 **뒤에** 비워 **거짓 FAIL** 을 낼 뻔함.

```bash
# 브리핑 시작 때 내가 찍어 주고, 보고에서 같은 값을 요구한다 (2026-09-13 직접 실행 확인)
sha256sum e2e/nuri-spot.spec.ts public/sitemap.xml src/lib/ranges.data.ts \
          src/lib/spotEvaluate.test.ts src/lib/spotEvaluate.ts   # → 5줄

netstat -ano -p tcp | grep -E ':417[0-9][^0-9]'   # 잔존 preview. 실측 0건(매칭 없음 = 종료코드 1)
git status --porcelain | wc -l                    # 시작·끝 값이 같아야 한다
```

⚠ **해시 값 자체는 여기 적지 않는다** — 이 문서가 §8 에서 경고하는 **낡는 수치**다. 매번 직접 찍어라.

### 7-5. 이 절이 못 보는 것

- **브리핑을 잘 써도 검증자가 상상하지 못한 부류는 그대로 남는다.** 3회 연속 새 결함이 나왔다는 것은
  **4회차에도 남아 있을 가능성**을 뜻한다. 이 세션이 3회에서 멈춘 것은 **충분해서가 아니라 세션이 끝나서**다.
- **위 공격 목록은 이 저장소가 실제로 밟은 것들**이다. 새 부류는 목록에 없다.
  **목록을 다 막았다고 "닫혔다"고 쓰지 마라** — 그게 §5 가 금지하는 공허한 통과다.
- **검증자의 자기 보고에 의존한다.** 정리·원복·미확인 목록은 전부 상대가 말해 주는 것이고,
  실저장소 편집 사고처럼 **말하지 않으면 모른다.** 그래서 §6 의 "내가 게이트를 독립 재실행" 이 대체 불가로 남는다.
- **브리핑 원문이 어디에도 없다.** `.claude/handoff/current.md` 에 "브리핑" 은 **0회** — 7-1 의 다섯 공통점은
  브리핑끼리 비교해 얻은 것이 아니라 **결과(결함 목록)에서 역추론**한 것이다. 무엇이 실제로 효과를 냈는지는 이 절도 모른다.
  다음 회차를 돌리는 사람은 **브리핑 원문을 handoff 에 남겨라** — 그래야 이 절이 언젠가 검증 가능해진다.
- **브리핑 품질 ↔ 결함 수의 인과는 관측 3회짜리 상관이다.** n=3 을 수치 근거로 쓰지 마라(§3-4 와 같은 규율).
- **회차를 언제 멈추는지 이 절은 모른다.** 멈추는 기준은 도메인 판단이고, 그건 §8 이 말하는 "코드를 읽어야 나오는 것" 이다.

## 8. 이 스킬이 못 보는 것 (정직하게)

- **절차만 다룬다.** *무엇을* 단언해야 하는지(도메인 판단)는 알려주지 않는다. 그건 코드를 읽어야 나온다.
- **음성 대조는 네가 상상한 회귀만 본다.** 상상하지 못한 회귀는 그대로 통과한다 —
  그래서 §6 에서 "겹치지 않는 각도"를 따로 요구하는 것이고, 그래도 남는 구멍이 있다.
- **소스를 변조하는 대조는 동시 편집과 상극이다.** 다른 에이전트가 같은 파일을 보고 있으면 돌리지 마라
  (동시 편집 절차는 `AGENTS.md`). 격리 사본으로 할 수 있으면 그쪽이 안전하다.
- **이 문서 자신이 한 번 틀렸다.** 초판 §1 의 예시 앵커 `num >= 0` 은 `regStatus.ts` 에 **0회**였다
  (계약 테스트의 *제목*에서 옮겨 적었다 — 제목은 **옛 버그**를 설명하는 문장이었다).
  "복사해 쓰라"고 적힌 명령도 **적힌 그대로 돌려 봐야 한다**는 것이 이 문서의 주장인데, 그 주장을 이 문서가 어겼다.
  같은 부류가 또 있다고 가정하고 읽어라 — 여기 적힌 경로·줄번호·수치는 전부 **인용 전에 다시 재는 대상**이다.
- **수치의 출처가 두 가지로 섞여 있다** — 이 문서 자신도 §3-4(교차 신호)의 대상이다.
  | 실제로 잰 것 (2026-09-13, vitest 4.1.11 · Node 24.15 · Git Bash) | §1 스크립트 4케이스(종료코드 0/1/9 포함) · 예시 앵커 1회·`null`→`0` 격리 실행 · 계약 3파일 `3 files / 35 tests` · `No test files found`·EXIT=1 · 줄끝 6파일 · mutation 대상 62/158 · §3·§5 가 가리키는 줄번호 전부 |
  |---|---|
  | **그날의 기록을 옮긴 것**(`.claude/handoff/current.md`) | 음성 대조가 틀린 9건 · `Tests no tests` · 8행 중 4행 소실 · 4608조합 · psql stdin · 검증자 사례 |
  뒤쪽은 **재현하지 않았다.** 같은 증상을 만나면 근거로 쓰되, 수치로 인용하려면 다시 재라.
- `npm run test:mutation` 의 사살률·생존자 목록은 **이 문서에 없다.** 실행하지 않았기 때문이다(소스를 덮어쓴다).
  돌린 사람이 수치를 적어 넣어라.
- 저장소가 바뀌면 위 수치는 전부 낡는다 — **재지 않고 인용하는 것 자체가 이 문서가 경고하는 부류다.**
